# Классы эквивалентности (Equivalence Partitioning)

## Что это за техника

**Классы эквивалентности** — способ разбить входные данные на группы, внутри которых система ведёт себя одинаково. Из каждой группы берём **один** тестовый случай (представителя). Если он проходит/падает, остальные значения из этой группы обычно ведут себя так же.

Идея: не тестировать все возможные значения (1, 2, 3, 4, 5 комнат…), а взять по одному из каждого класса.

---

## Классы эквивалентности для validate_queue_eligibility()

### 1. profile (наличие анкеты)

| Класс            | Диапазон значений     | Ожидаемый результат | Представитель в тесте |
|------------------|------------------------|----------------------|------------------------|
| Валидный         | profile — объект      | Проверка продолжается | MockUserProfile(...)  |
| Невалидный       | profile = None        | FAIL (нет анкеты)    | None                  |

**test_eq_profile_valid** — представитель валидного класса (profile заполнен).  
**test_eq_profile_invalid** — представитель невалидного класса (profile = None).

---

### 2. Совместимость с детьми

| Класс            | Условие                                   | Ожидаемый результат | Представитель              |
|------------------|-------------------------------------------|----------------------|----------------------------|
| Совместимо       | for_children=True ИЛИ has_children=False  | Ошибки нет           | (for_children=True, has_children=False) |
| Несовместимо     | for_children=False И has_children=True    | FAIL (не для детей)  | (for_children=False, has_children=True) |

**test_eq_children_forbidden_but_user_has** — представитель несовместимого класса: животное не для детей, а у пользователя есть дети.

---

### 3. Совместимость с другими животными

| Класс            | Условие                                        | Ожидаемый результат | Представитель                 |
|------------------|------------------------------------------------|----------------------|-------------------------------|
| Совместимо       | with_other_animals=True ИЛИ has_other_animals=False | Ошибки нет       | (with_other_animals=True, has_other_animals=False) |
| Несовместимо     | with_other_animals=False И has_other_animals=True   | FAIL (не уживается)  | (with_other_animals=False, has_other_animals=True) |

**test_eq_pets_forbidden_but_user_has** — представитель несовместимого класса: животное не с другими, а у пользователя уже есть питомцы.

---

### 4. Тип жилья (house vs apartment)

| Класс            | Условие                                   | Ожидаемый результат |
|------------------|-------------------------------------------|----------------------|
| Совместимо       | requires_house=False ИЛИ housing_type='house' | Ошибки нет        |
| Несовместимо     | requires_house=True И housing_type='apartment' | FAIL (нужен дом)  |

Тест **test_eq_profile_valid** одновременно проверяет валидный профиль и совместимость по типу жилья (requires_house=True, housing_type='house').

---

## Почему этих тестов достаточно

Для EP достаточно **по одному представителю** из каждого релевантного класса:

- profile: валидный и невалидный
- дети: несовместимый случай (совместимый уже покрыт другими тестами)
- питомцы: несовместимый случай

Так мы проверяем логику классов эквивалентности, не дублируя лишние тесты.
